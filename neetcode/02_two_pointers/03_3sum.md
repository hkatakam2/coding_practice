### question
Given an integer array `nums`, return all the triplets `[nums[i], nums[j], nums[k]]` where `nums[i] + nums[j] + nums[k] == 0`, and the indices `i`, `j` and `k` are all distinct.
The output should not contain any duplicate triplets. You may return the output and the triplets in any order.

### 1. Restating the Question

Find unique triplets in integer array that sum to exactly 0.

### 2. Clarifying Questions & Confirming I/O

**Input:** `nums = [-1, 0, 1, 2, -1, -4]`
**Output:** `[[-1, -1, 2], [-1, 0, 1]]`

* **Q:** Array length less than 3? **A:** Return empty list.
* **Q:** Array with all zeros `[0, 0, 0, 0]`? **A:** Return `[[0, 0, 0]]`.
* **Q:** Order of output matter? **A:** No.
* **Q:** Can same index be used twice? **A:** No, `i, j, k` distinct.

### 3. By Hand Example

Input: `[-1, 0, 1, 2, -1, -4]`

1. **Sort:** `[-4, -1, -1, 0, 1, 2]`
2. **Fix -4:** Pointers at `-1` (left) and `2` (right). Sum = -3. Too small. Move left pointer. Highest possible pair sum is 1. No match for -4.
3. **Fix -1 (first):** Pointers at `-1` (left), `2` (right). Sum = 0. **Match:** `[-1, -1, 2]`. Move left and right inwards.
* Pointers at `0` (left), `1` (right). Sum = 0. **Match:** `[-1, 0, 1]`.


4. **Fix -1 (second):** Skip. Same as previous fixed number. Avoids duplicate triplets.
5. **Fix 0:** Pointers at `1`, `2`. Sum = 3. Too big. Move right pointer. Exhausted.
**Output:** `[[-1, -1, 2], [-1, 0, 1]]`

### 4. Brainstorming & Complexity

* **Brute Force:** 3 nested loops checking every combination. O(N³) time, O(1) space. Too slow.
* **Hashing:** 2 loops to find sum, lookup complement in hash set. O(N²) time, O(N) space. Problem: Deduplicating triplets requires sorting each triplet and storing in another set. Messy.
* **Sort + Two Pointers:** Sort array. Iterate first element. Use two pointers squeezing inwards for remaining elements. Skip adjacent duplicates. O(N²) time. O(1) or O(N) space depending on sort algorithm.

### 5. Suggested Solution

Prefer **Sort + Two Pointers**. Matches hand-trace. Cleanest duplicate handling without nested hash sets. Straightforward to explain.

**Iteration 4: Patching Edge Cases.**

```python
def threeSum(nums):
    # PATCH 1: Array length < 3
    if len(nums) < 3:
        return []
        
    nums.sort()
    res = []
    
    for i in range(len(nums)):
        # PATCH 2: Early exit. If smallest number is > 0, sum can never be 0.
        if nums[i] > 0:
            break 
            
        if i > 0 and nums[i] == nums[i-1]:
            continue
            
        left = i + 1
        right = len(nums) - 1
        
        while left < right:
            current_sum = nums[i] + nums[left] + nums[right]
            
            if current_sum < 0:
                left += 1
            elif current_sum > 0:
                right -= 1
            else:
                res.append([nums[i], nums[left], nums[right]])
                left += 1
                right -= 1
                
                while left < right and nums[left] == nums[left - 1]:
                    left += 1
                while left < right and nums[right] == nums[right + 1]:
                    right -= 1
                    
    return res

```

### 8. Complexity & Optimizations

* **Time Complexity:** `O(N log N)` for sorting + `O(N²)` for the nested loop traversal. Overall Time Complexity dominates at **`O(N²)`**.
* **Space Complexity:** `O(1)` or `O(N)`. Python's `sort()` (Timsort) takes `O(N)` space in the worst case.
* **Optimization check:** The `if nums[i] > 0: break` added in Iteration 4 is the primary micro-optimization. Since array is sorted, if the fixed number becomes positive, all subsequent numbers are positive. Squeeze search is impossible. Saves unnecessary loop cycles. No further optimization needed; `O(N²)` is optimal for 3Sum.
