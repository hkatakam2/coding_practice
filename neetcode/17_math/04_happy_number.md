### question
A non-cyclical number is an integer defined by the following algorithm:

Given a positive integer, replace it with the sum of the squares of its digits.
Repeat the above step until the number equals 1, or it loops infinitely in a cycle which does not include 1.
If it stops at 1, then the number is a non-cyclical number.
Given a positive integer n, return true if it is a non-cyclical number, otherwise return false.

**1. Restating the Question**
Given positive integer `n`, repeatedly replace it with sum of squares of its digits. If it reaches 1, return `True` (non-cyclical). If it loops infinitely, return `False` (cyclical).

**2. Clarifying Questions & Confirmations**

* **Input:** Positive integer `n`. (Max size? Assume standard 32-bit int).
* **Output:** Boolean. `True` if reaches 1, `False` if stuck in cycle.
* **Confirm:** Are there only two outcomes (reaches 1 or cycles)? Yes. It will never grow infinitely because sum of squares of digits shrinks large numbers (e.g., 9,999,999,999 -> 10 * 81 = 810).

**3. By-Hand Example**
Input: `n = 19`

* 1² + 9² = 82
* 8² + 2² = 68
* 6² + 8² = 100
* 1² + 0² + 0² = 1
Output: `True`

Input: `n = 2`

* 2² = 4 -> 16 -> 37 -> 58 -> 89 -> 145 -> 42 -> 20 -> 4 (Cycle detected!)
Output: `False`

**4. Brainstorming & Complexity**

* **Approach A: Simulation + Hash Set.** Track seen numbers. If we see 1, return True. If we see a previously seen number, return False.
* *Time:* $O(\log n)$. Finding digits takes $\log_{10} n$ steps. Maximum number drops below 810 quickly, bounding loop iterations to a constant.
* *Space:* $O(\log n)$ to store set (practically bounded to ~243 or 810 entries).


* **Approach B: Floyd's Cycle Detection (Tortoise and Hare).** Fast pointer does 2 steps, slow does 1. If they meet at 1, True. If they meet elsewhere, False.
* *Time:* $O(\log n)$.
* *Space:* $O(1)$.



**5. Suggested Solutions**
Prefer Approach A. Simulation + Hash Set exactly mimics the by-hand step 3. Simple, straightforward, easy to read.

**8. Complexity & Optimizations**

* **Space Complexity Note:** The hash set scales up to $O(\log n)$ space initially, but since max sum for a 10-digit number (max 32-bit int) is $9^2 \times 10 = 810$, the set size strictly caps at 810. Effectively $O(1)$ space.
* **Optimization (True $O(1)$ Space):** If we strictly cannot allocate a set, use Floyd's cycle finding (Approach B).

*Optimization Implementation (Tortoise & Hare):*

```python
def is_non_cyclical_optimized(n):
    if n <= 0: return False
    
    slow = n
    fast = get_next(n)
    
    while fast != 1 and slow != fast:
        slow = get_next(slow)
        fast = get_next(get_next(fast))
        
    return fast == 1

```
